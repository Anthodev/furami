# Frozen media source build and official Qt kit

`stack.lock.json` freezes Ubuntu 24.04 x86_64 by OCI digest and a signed APT snapshot. `build-apt-closure.json` names 408 installed build-environment packages and 317 downloaded `.deb` SHA256 hashes. Upstream source archives pin mpv 0.41.0 (client API 2.5.0), libplacebo 7.360.1, FFmpeg 8.1.2 and CXX-Qt 0.10.0. Five separate official Qt Online Installer archives pin Qt 6.11.2 `linux_gcc_64`: qtbase, qtdeclarative, qtsvg, qtshadertools and ICU. Each `.7z` has a measured SHA256 and its matching published SHA1 sidecar recorded in the lock. The recipe checks both hashes before unpacking with snapshot-pinned `python3-py7zr` 0.11.3; direct `7z` extraction failed on Qt symlinks and is not used. Qt's own installed `config_*.opt`, `config_*.summary` and SBOM files retain the vendor build configuration and license metadata. The APT closure includes NASM for FFmpeg's x86 assembly, `libxss-dev`/`libxpresent-dev` for mpv X11, and `lld` for the application bridge. The five X11 pkg-config prerequisites are checked inside Ubuntu. `vulkan_headers` is libplacebo's exact gitlink and supplies Vulkan 1.4 headers absent from Noble. No media system-package fallback, local source patches, `--enable-nonfree`, host-root installation or Git submodule network fetches are used.

`sources.mpv.build_flags` freezes `-Djpeg=disabled`. This drops mpv's optional libjpeg image writer, not FFmpeg's `libavcodec` MJPEG decoder needed for capture. The container records `readelf --dynamic` for `mpv` and `libmpv.so` and fails if either directly needs `libjpeg.so`; the normal decoder, VO, context and filter checks remain mandatory. An earlier compiled candidate had a direct `libjpeg.so.8` dependency and is not the post-freeze deliverable.

On a clean checkout with Python 3, working rootless Podman, network access and enough disk/RAM for the media source builds and official Qt archive extraction:

```sh
python3 packaging/media/build.py "$HOME/furami-media-run-1"
python3 packaging/media/build-twice.py "$HOME/furami-media-repro"
python3 -m unittest discover -s packaging/media -p build_tests.py
```

Use new output directories for each command. `build.py` downloads every named media source and official Qt archive, verifies actual SHA256 (and Qt's published SHA1) before read-only mounting inside the container, and records `OUTPUT/prefix/`, media build flags, FFmpeg/Meson configuration, vendor Qt configure files/SBOM, exact APT package versions and downloaded `.deb` SHA256, diagnostics, and a manifest with every delivered file/symlink hash. Installing Qt applies the narrow Linux relocation used by aqt 3.3.0: vendor `.pc` prefixes and any `.prl`/`.la` build paths are rewritten for `/out/prefix`, and `bin/qt.conf` sets `Prefix=..`. `OUTPUT/qt-relocation.json` records old/new SHA256 for each changed file. The selected qmake/qmake6 binaries contain no aqt binary-prefix markers; Qt's relative CMake configs are left intact. The vendor's `Qt6BuildInternalsExtra.cmake` retains its original build-only path, as in aqt; do not treat it as an application link path. `build-twice.py` performs two clean container builds with a shared verified download cache, compares all prefix files/symlinks and APT provenance, and only then writes `reproducibility.json`. A failed run retains `build.log` and partial output but no success manifest.

`OUTPUT/prefix/bin/mpv`, `bin/ffmpeg`, `lib/libmpv.so`, `lib/libplacebo.so`, `lib/libav*.so`, Qt libraries, pkg-config files and Qt CMake packages come from that private prefix. The recipe checks exact FFmpeg/libplacebo/pkg-config versions and prefixes, the mpv client ABI against `sources.mpv.client_api`, Qt version, `gpu-next`/`x11vk` listings, FFmpeg decoder/filter listings, X11 pkg-config prerequisites and dynamic loader paths for libmpv/mpv. The device-listing check accepts input-capable `D`/`DE` rows and exact comma-separated aliases such as `video4linux2,v4l2`, not output-only devices. CLI listings alone do **not** prove live Vulkan rendering, hardware input, mpv-native `format`, lavfi bridge behavior, or legal redistribution. Hardware probe evidence remains local; final AppImage inventory is the separate FUR-005 publication gate.

CXX-Qt's source archive and SHA256 are locked as a Cargo bridge input; neither Qt's prebuilt kit nor this media recipe installs its Rust crate closure. The application Cargo.lock and native bridge build must consume precisely 0.10.0. The named Ubuntu packages are build-environment provenance, **not** a list of redistributed AppImage components; static glslang/SPIRV-Tools archives named by the libplacebo link are separately covered in the [core license audit](LICENSE-AUDIT.md). Three completed local build manifests matched at SHA256 `dca703670e034de71fc45db2f79c1490ad454fb9131b93da1c99a5cb989d791a`, and hardware probe transcripts are kept outside this tracked recipe directory. This qualifies the media source build, **not** the legal closure of a release AppImage: after FUR-003, FUR-005 must inventory the actual package and deliver applicable source access, notices and GPL/LGPL conditions before publication.
