The prefix lists `gpu-next` and `x11vk`; build-G's required X11 output cannot be relabeled LGPL. [mpv's v0.41.0 `Copyright`](https://github.com/mpv-player/mpv/blob/v0.41.0/Copyright) declares GPL-2.0-or-later by default, and says `-Dgpl=false` excludes GPL-only X11 output files. Disabling mpv's optional JPEG image **writer** does not remove FFmpeg's MJPEG decoder or change GPL status.
- **FFmpeg:** The recorded configure line has `--enable-shared --disable-static --enable-gpl --enable-filter=eq --enable-filter=hqdn3d --enable-decoder=mjpeg` and V4L2/Pulse inputs. It does **not** enable `--enable-nonfree`; `ffmpeg-config.mak` records `CONFIG_GPL=yes`, `!CONFIG_NONFREE=yes`, and both filters enabled. [FFmpeg's licensing page](https://ffmpeg.org/legal.html) says GPL parts make FFmpeg GPL-2.0-or-later; both [eq](https://github.com/FFmpeg/FFmpeg/blob/n8.1.2/libavfilter/vf_eq.c) and [hqdn3d](https://github.com/FFmpeg/FFmpeg/blob/n8.1.2/libavfilter/vf_hqdn3d.c) carry GPL-2.0-or-later headers. ## Distribution boundary

This is the mandatory **core media stack** audit for FUR-002. Installed APT packages and Qt build tools are build provenance, not automatically shipped components. Conversely, statically incorporated Ubuntu archive objects require source and notices even if no corresponding `.so` is staged. Using system libraries instead of bundling them does not cancel GPL obligations when distributing a program linked to GPL libmpv/FFmpeg; [GNU's linking FAQ](https://www.gnu.org/licenses/gpl-faq.html#GPLStaticVsDynamic) explains the combined-work issue.

Before publishing a combined Furami executable, satisfy GPL terms for its selected compatible version, corresponding source and build/install scripts, with media libraries' matching source and notices. GPL-2.0-or-later mpv/FFmpeg permit a GPLv3-compatible route for LGPLv3 Qt, subject to actual linked and static code. For dynamically linked Qt LGPLv3 modules, retain LGPL/GPL texts, matching Qt source access and notices, and ensure users can replace the shared libraries with compatible modified versions; supply installation information where LGPLv3 requires it ([Qt LGPLv3 terms](https://doc.qt.io/qt-6/lgpl.html)). Account separately for libplacebo LGPLv2.1+ and incorporated glslang/SPIRV objects. AppImage format itself adds no requirement for a hand-authored SPDX dossier per file.
