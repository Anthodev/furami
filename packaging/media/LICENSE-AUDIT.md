## License facts from build-G

- **mpv:** Meson used `-Dgpl=true -Dlibmpv=true -Dvulkan=enabled -Dx11=enabled -Dwayland=disabled -Djpeg=disabled`, with shared libraries. The prefix lists `gpu-next` and `x11vk`; build-G's required X11 output cannot be relabeled LGPL. [mpv's v0.41.0 `Copyright`](https://github.com/mpv-player/mpv/blob/v0.41.0/Copyright) declares GPL-2.0-or-later by default, and says `-Dgpl=false` excludes GPL-only X11 output files. Disabling mpv's optional JPEG image **writer** does not remove FFmpeg's MJPEG decoder or change GPL status.
- **FFmpeg:** The recorded configure line has `--enable-shared --disable-static --enable-gpl --enable-filter=eq --enable-filter=hqdn3d --enable-decoder=mjpeg` and V4L2/Pulse inputs. It does **not** enable `--enable-nonfree`; `ffmpeg-config.mak` records `CONFIG_GPL=yes`, `!CONFIG_NONFREE=yes`, and both filters enabled. [FFmpeg's licensing page](https://ffmpeg.org/legal.html) says GPL parts make FFmpeg GPL-2.0-or-later; both [eq](https://github.com/FFmpeg/FFmpeg/blob/n8.1.2/libavfilter/vf_eq.c) and [hqdn3d](https://github.com/FFmpeg/FFmpeg/blob/n8.1.2/libavfilter/vf_hqdn3d.c) carry GPL-2.0-or-later headers. Keep nonfree disabled: combining GPL and FFmpeg nonfree components would block redistribution.

## Current recipe FFmpeg source patch

This section describes the current source recipe; it is separate from the frozen build-G facts above and makes **no release-clearance claim**.

- **Authoritative patch pin.** [`stack.lock.json`](stack.lock.json) `sources.ffmpeg.patches` is an ordered array that names each FFmpeg source patch by repository-relative path and SHA256; the lock, not this audit, carries the current digest, which changes whenever a patch changes. The FFmpeg 8.1.2 upstream archive stays pinned to its existing SHA256 `464beb5e7bf0c311e68b45ae2f04e9cc2af88851abb4082231742a74d97b524c` that appears in the table above.
- **Source reconstruction.** The provider source is the pristine upstream tar plus the ordered patches applied in array order, each verified against its locked SHA256 first; a path/hash mismatch or a failed application fails closed. `source-patches.py` performs the check/apply and records an applied receipt, and the patch bytes are carried in the build-input snapshot and the output manifest.
- **Single current patch.** The array currently lists `patches/ffmpeg-v4l2-latest.patch`, Furami-authored code that adds a private boolean V4L2 AVOption `furami_latest` (default `0`/off) to FFmpeg `libavdevice`. The option stays off for every default path and for any other consumer; Furami opts in only from its own capture lavf input options. When enabled it selects the newest completed single-planar captured buffer within a bounded drain instead of the oldest queued one. It is compiled only into the privately bundled provider; it is not a change to a system FFmpeg, and no host FFmpeg is modified or shipped.
- **License attribution.** The patched `libavdevice/v4l2.c` file retains its upstream LGPL-2.1-or-later header. The bundled FFmpeg configuration enables GPL components, so the resulting FFmpeg build remains GPL-2.0-or-later; this does not make the original file GPL-only, and `--enable-nonfree` stays disabled. The patch bytes are bundled inside the AppImage at `usr/share/licenses/media/ffmpeg/patches/ffmpeg-v4l2-latest.patch` and in the corresponding source materials under `furami/packaging/media/patches/`, together with the media sources. The existing provider build command, `packaging/media/build.py` with a new output directory and the source archive cache, reconstructs the patched source from these inputs.
- **Ownership intent (not a qualification).** The opt-in path retires capture by stopping streaming and closing the descriptor synchronously, serialized against packet callback requeues. An independent shared owner retains mapped buffers and callback state until the last packet reference is released; late callbacks must not requeue after retirement or access the freed capture context. Runtime qualification on affected hardware, and end-to-end latency behavior, are **not** established by this audit.

## Distribution boundary

Installed APT packages are build provenance, not automatically shipped components. Conversely, statically incorporated Ubuntu archive objects require source and notices even if no corresponding `.so` is staged. Using system libraries instead of bundling them does not cancel GPL obligations when distributing a program linked to GPL libmpv/FFmpeg; [GNU's linking FAQ](https://www.gnu.org/licenses/gpl-faq.html#GPLStaticVsDynamic) explains the combined-work issue.

Before publishing a combined Furami executable, satisfy GPL terms for its selected compatible version, corresponding source and build/install scripts, with media libraries' matching source and notices. Account separately for libplacebo LGPLv2.1+ and incorporated glslang/SPIRV objects. AppImage format itself adds no requirement for a hand-authored SPDX dossier per file.

**FUR-005, after FUR-003:** Inventory the actual release AppImage and outer runtime, ELF and `dlopen` closure, and linked application dependencies, including GPUI, AccessKit and the CXX bridge for V4L2. Map shipped bytes to sources and fulfill notices, source access, LGPL replacement and applicable GPL obligations. Build-G prefix and prototype AppImage evidence do not prove release package scope or legal redistribution clearance.
