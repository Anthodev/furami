# AppImage type-2 runtime recipe

Builds only the x86_64 type-2 runtime. This recipe does **not** bundle Furami's AppDir or run appimagetool.

```sh
python3 packaging/appimage-runtime/build.py /absolute/new-output
python3 packaging/appimage-runtime/build-twice.py /absolute/new-comparison
```

Requires rootless Podman, HTTPS access for initial input acquisition, and space for 229 MB of APK downloads plus the build. `--source-cache /absolute/cache` shares checked inputs; default is `$XDG_CACHE_HOME/furami/appimage-runtime` (or `~/.cache/furami/appimage-runtime`). Outputs must be new absolute paths. A successful build writes `runtime-x86_64`, `manifest.json`, `licenses/`, package/toolchain records, raw link map, and `build.log`. A failed build has no manifest; inspect its build log. The two-build helper creates fresh independent containers and compares runtime bytes, package closure, manifest and link map. Clang creates a random `/tmp/runtime-xxxxxx.o` filename when compiling/linking in one step; it appears in the map, changing its raw SHA256 in the manifest but not the runtime binary. `comparison.json` records raw hashes and offsets, the two temporary filenames and occurrence count, then accepts the run **only** if removing that single filename class makes the complete maps equal and the manifest differs solely in its correctly recorded raw map hash. Any other variance fails.

`runtime.lock.json` pins upstream type2-runtime commit `75849dce7cc37e4319b633df1f116ca895c71a12`, FUSE 3.15.0, squashfuse 0.5.2, the upstream FUSE mount patch, Alpine 3.21 linux/amd64 **platform manifest**, the original base APK database and both signed APKINDEX archives. It selects **138 APK archives** by version, whole-file SHA256, Alpine index checksum, aports commit and package license field. The immutable base still records its original OpenSSL/zlib versions; the selected overlay explicitly replaces `libcrypto3`, `libssl3` and `zlib`. The effective installed closure has **150 unique package names**, computed from the base map followed by the selected overlay. Old versions, duplicate records and unexpected packages fail the installed-state guard.

Before reading index records, the producer invokes `apk verify` and a local-repository `apk update` inside that exact base with networking disabled, using only the trusted keys already present in the base. A `.SIGN.RSA.*` tar member alone is not authentication. Every selected APK is SHA256-checked, signature-verified and indexed by Alpine's own `apk index`; its generated package identity, license and aports commit must match the authenticated upstream index. The index `C` checksum is **not** a whole-file SHA-1 or SHA256. Logs and command receipts remain in the private source cache. The container installs only the explicit sorted archive list from the lock, never a wildcard over cache contents. Stale APKs in a reusable cache cannot add packages.

`alpine-source.lock.json` distinguishes binary APK SHA256 from corresponding source provenance for linked musl, zstd, zlib, secure mimalloc and GCC startup objects. It pins each exact-commit aports `APKBUILD`, upstream archive, every patch/input and their SHA256/SHA512 correspondence. All five recipes and **61 source archives/patches** are checked before a normal build. The targeted zlib `1.3.2-r1` refresh retains the unchanged `1.3.2` upstream archive and includes the exact-commit `CVE-2026-85091.patch`; omitting that patch is not matching source.

Alpine **binary bootstrap APKs and the base-image closure are private inputs**, excluded from public candidate/source assets. Public materials retain the actual runtime, application and Qt corresponding sources, the complete linked Alpine source closure, recipes, locks, notices and provenance. Excluding binary build tools does not clear their redistribution terms; they are not publicly distributed. Public assets do **not** promise a complete offline Alpine bootstrap.

A retained private generation contains both authenticated indexes, all 138 selected APKs, runtime sources/notices, all five linked source closures, the exact OCI manifest/config/layers, recipe snapshots and authentication/offline-restoration receipts. It must stay outside candidate and evidence-upload roots. Its relative SHA256 inventory is checked separately from public source/license readiness:

```sh
python3 packaging/appimage-runtime/build.py --check-private-inputs \
  --source-cache /absolute/private-generation/sources
```

This integrity/completeness check performs no network access or build and does not re-run signatures or prove public clearance. It requires the retained apk-generated selected index, installed-package output and restored raw manifest, and checks them against the exact selected closure, effective base overlay and immutable manifest. Successful index/APK/offline-SDK receipts must bind the current runtime/source locks, index and selected-APK hashes, producer/provisioning recipes, logs and derived outputs; same-base success receipts from another closure are not sufficient. Actual restoration must use isolated image storage, unavailable networking and the exact digest reference with `--pull=never`. Loading a converted archive or matching only a config ID is not proof of preserving the upstream manifest. Keep historical raw receipts/inventories unchanged when emitting a new bound proof generation; do not delete or repurpose the host image store.

Alpine CDN retains no immutable URL for a historical APKINDEX; changed live bytes fail SHA256 checks rather than rolling forward. Retain authenticated private generations without overwriting older mismatching caches. A digest-pinned OCI image alone does not freeze its package repository. Initial acquisition requires HTTPS and a locally available/pullable immutable base; compilation itself has networking disabled. Keep private bootstrap retention and public corresponding-source clearance as distinct requirements.

Build uses upstream runtime Makefile flags and patches bytes `AI\x02` at ELF offsets 8–10 **after** stripping, matching upstream `scripts/build-runtime.sh`. FUSE's mount patch changes fusermount lookup to `FUSERMOUNT_PROG`, which the upstream runtime sets when executing an AppImage. Runtime version marker is replaced with the pinned commit, as upstream CI does. `manifest.json` includes link-map archive membership, observed installed package closure, compiler/linker versions, exact recipes and build flags, artifact hash, license file hashes, and source references. ELF verification rejects a wrong architecture, missing type-2 magic, dynamic interpreter or `DT_NEEDED` library. It cannot prove which dead-stripped functions from a static archive remain in the executable; the archive list is a conservative inclusion record, not a per-function SBOM.

Link audit attributes direct musl `rcrt1.o`, `crti.o`, `crtn.o`, GCC `crtbeginS.o`/`crtendS.o` (GPL-3.0-or-later WITH GCC-exception-3.1) and the compiled runtime object as well as static archive members. Unexpected direct objects or archives fail the manifest gate. Successful output also includes `relink/` with the four verified upstream source/patch archives, pinned recipe/locks and operative modified-libfuse build instructions; `notice_files` and `relink_files` map each shipped notice/source/tool to SHA256.

Bundled notices cover the root runtime MIT license plus its `runtime.c` Alexander Larsson MIT notice, FUSE linked library code (LGPL-2.1-only), squashfuse (BSD-2-Clause), musl (MIT plus COPYRIGHT exceptions), zstd (BSD-3-Clause selection), zlib (Zlib), secure mimalloc (MIT), and the actually linked GCC startup objects (GPL-3.0-or-later with GCC Runtime Library Exception 3.1). Upstream runtime `LICENSE` omits mimalloc; this recipe supplies its notice. Alpine's SPDX package fields cover build-only tooling too; they do **not** imply every installed tool is linked. Static libfuse requires matching source and ability to modify/relink, not an invented source offer. `relink/RELINKING.md` documents a modified-libfuse rebuild route and explicit distribution gate: no AppImage publication until FUR-005 supplies complete recipient-accessible sources/toolchain and reviews license terms. This qualification kit alone is not legal compliance certification.
